## 1. 今回の範囲

- アプリ名：**Squat for Mac**。所有者が提供した`Assets/AppIcon.png`を利用。
- 初期版：**0.9.0**。まずGitHubを非公開にして、本人の日常利用と監査の確認を進める。
- リポジトリ：`rin999999334/squat-for-mac` を非公開で作成済み。公開化・一般配布は別途の判断とする。
- 主な価値：前面のAIアプリを使う時間に、短い運動のきっかけを作る。実装していない自動化を主な訴求に使わない。
- 新機能の追加・公開範囲の変更・コードライセンスの選択は所有者が決める。

## 5. 初見で伝える順番

READMEの上部で「何に使うか」「実際の動き」「インストール」「権限・プライバシー」「できないこと」を順に伝えます。GitHubもREADMEを、プロジェクトの有用性と使い方を伝える場所として案内しています。[GitHub公式](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)

公開時に用意する素材は次の最小限です。

1. 提供アイコン。別のソーシャルカバーは作らない。
2. 約20秒の実際の操作デモ。実データ・会話・他アプリの個人情報は映さない。
3. Home・メニュー・カメラ・Totalの、架空データであると分かるスクリーンショット。
4. READMEの日本語版と英語版、最短の使い方、既知の制約。
5. バージョンごとの変更点・対応環境・署名と公証の状態・既知の問題。

20秒デモの構成案：0–4秒「AIアプリ別の利用時間」→4–8秒「運動の通知」→8–15秒「Go Squat、実際に数える」→15–20秒「記録とTotalカード」。通知を待たずに撮るなら、テスト用の表示であることを明示します。

## 6. 発見してもらう導線

機能はシンプルに、戦略は巧妙に。これは以下の導線の仮説です。Star数の増加を保証するものではありません。

- **note**：開発した理由、20秒デモ、実際の使い方、映像を保存しない設計、既知の制約、GitHubへのリンクを載せる。
- **X**：同じデモと短い利用場面、GitHubリンクを載せる。Today/Totalを共有する体験は任意とし、投稿やStarを利用条件にしない。
- **GitHub**：README冒頭で実物を見せ、対象ユーザー・対応環境・最短導入手順を揃える。公開時に正確な説明と`macos`、`swift`、`swiftui`、`menu-bar`、`productivity`、`exercise`など実装に合うTopicsを検討する。[Topicsの公式案内](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics)
- **アプリ内共有**：本人が見せたいToday/Total画像と正式なGitHub URLを使う。自動投稿・自動追跡を加えない。
- **継続**：不具合への対応と小さな改善をリリースノートに残す。最初から偽のStarバッジ・ダウンロード実績・効果の数値を置かない。

note・Xの告知は、公開済みのGitHub Releaseと実際のダウンロード先を確認してから揃えて出します。告知の投稿自体はこの作業に含めません。
